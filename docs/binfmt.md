# cyber-spine 可执行镜像格式（`.csp`）

状态：设计冻结（v1）
适用范围：磁盘容器布局、对齐与 padding、元数据表、内容哈希、加载期校验
依赖：`docs/isa.md` 定义指令语义；本文件定义**字节布局**。

> **本文件是格式的唯一规范。** 代码尚未编写；将来实现时必须服从本文件。
> 若实现与本文件冲突，以本文件为准。附录 A 给出将来用 `binrw` 实现时的属性映射备忘。

---

## 0. 三条前置结论

1. **一个文件 = 一个动作 = 一个执行单元。** `单元 ≡ 程序 ≡ 程序镜像`。
   因此不存在 unit 表，`entry` 恒为 0 且不落盘；`layer`、`fuel` 是固定头里的标量。
2. **镜像在 bind 之前。** 头段携带**名字**，代码段的 `imm` 是**逻辑下标**（头段表的下标）。
   名字 → rig 物理下标的解析发生在加载期（§13.2），缺失的名字绑到 VOID（§13.3）。
   所以本格式**与 rig 无关**，同一个动作可以跨模型复用。
3. **`group` 不是文件的一部分。** 它是汇编期伪指令，与 `ELSE`/`END`/`WHILE` 同构地展开掉。
   由此得到一个关键性质：**磁盘上的指令下标与 bind 后的指令下标一一对应**，
   跳转偏移在 bind 期不需要重定位，`pc` 恒等映射。

## 1. 总原则

| 原则 | 内容 |
|---|---|
| P1 | **磁盘表示固定小端。** 内存表示用宿主字节序，二者只在读写处转换。 |
| P2 | **代码段裸放。** 不经过任何通用序列化编解码器；它永远是 8 字节定长小端 `u64`。 |
| P3 | **布局全推导。** 所有段的位置由固定头的字段算出，文件里**没有任何冗余的长度字段或偏移字段**。 |
| P4 | **规范形式由构造保证。** 见 §8。 |
| P5 | **自包含。** 无常量池、无外部符号表、无指针、无重定位表。 |
| P6 | **加载期全量校验，运行期零成本。** 见 §9。 |

P3 的推论：**本格式里唯一存在的 padding 是"固定头凑够 8 的整数倍"这一处**（§4.1）。
其余位置没有任何空隙，也就不存在"padding 字节该填什么"的问题。

## 3. 文件总览

```
偏移                              长度
[0        .. 96)                  96       固定头（§4）
[96       .. 96+8N)               8N       代码段：N = header.code_len 条指令（§5）
[..       ..  ..)                 可变     元数据表（§6），顺序固定：
                                            muscles → sensors_f → sensors_i → vars_f → vars_i
[file_len-32 .. file_len)         32       content_hash = blake3(前面全部字节)（§7）
```

- 代码段起始偏移**恒为 96**（96 % 8 == 0，故代码段天然 8 字节对齐）。
- 文件必须**精确结束**于哈希；哈希之前不允许任何尾随字节。
- 元数据表之间**零间隙**。表内元素变长（名字是 NUL 结尾串），因此表的字节长度由元素逐个推导。
- 最小合法文件长度：`96 + 8 + 32 = 136`（至少一条指令，即 `HALT`）。

## 4. 固定头（96 字节，全部小端）

| off | sz | 字段 | 类型 | 说明与校验 |
|---|---|---|---|---|
| 0 | 4 | `magic` | `b"CSPX"` | 大端读者会看到 `"XPSC"` ⇒ 免费获得字节序检测 |
| 4 | 2 | `format_version` | u16 | 高字节 major，低字节 minor。major 必须相等，minor 必须 ≤ 本加载器 |
| 6 | 2 | `isa_version` | u16 | `isa.md` 的指令编码与语义版本 |
| 8 | 2 | `cycle_table_version` | u16 | `isa.md` §6.3 的**周期计费表版本**；缺了它 `cycles_per_tick` 没有指称对象 |
| 10 | 2 | `flags` | u16 | 保留，**必须为 0**（未定义位一律拒绝，不做"忽略未知位"） |
| 12 | 4 | `file_len` | u32 | 必须精确等于文件实际长度 |
| 16 | 4 | `code_len` | u32 | 指令**条数**；≥ 1；`code[code_len-1]` 必须是 `HALT` |
| 20 | 2 | `layer` | u16 | 该动作声明的层号，VM 只搬运（§9.2） |
| 22 | 2 | `reserved0` | u16 | 必须为 0 |
| 24 | 4 | `muscle_count` | u32 | `isa.md` §8.1 的 `Task.values` / `set_mask` 长度 |
| 28 | 4 | `sensor_f_count` | u32 | 浮点 sensor 数，**必须 ≥ `muscle_count`**（§6.2 读回不变量） |
| 32 | 4 | `sensor_i_count` | u32 | 整数 sensor 数 |
| 36 | 4 | `var_f_count` | u32 | 任务浮点变量数（§2.4） |
| 40 | 4 | `var_i_count` | u32 | 任务整数变量数 |
| 44 | 4 | `hz` | u32 | tick 率，**必须 > 0**。`dt = 1/hz`（§6.1） |
| 48 | 4 | `cycles_per_tick` | u32 | **必须 ≥ 该 `cycle_table_version` 表中最贵指令的周期数**（§10 #10） |
| 52 | 4 | `fuel` | u32 | 每次恢复的指令预算（§7）。v1 缺省 **4096**。0 是合法值 |
| 56 | 4 | `max_wait_bits` | u32 | `f32::from_bits` 得到的单次 `WAIT` 上界，缺省 600.0；必须非负有限 |
| 60 | 4 | `reserved1` | u32 | 必须为 0 |
| 64 | 32 | `reserved2` | 4 × u64 | 必须全为 0。预留给未来的 data section（`isa.md` §12「批量数据段」） |

**为什么这些标量在固定头而不是"程序段"**：加载器永远要先读它们，固定偏移省一次解析；
更重要的是，**计数/长度一致性校验必须在分配内存之前完成**（§9.1 C5），固定头让这件事不需要任何解析就能做。

### 4.1 padding 规则（本格式的全部内容）

1. **固定头长度为 96，是 8 的倍数**，因此代码段起始偏移 96 天然 8 字节对齐。
   这条是**格式不变量**：将来扩固定头**必须**保持 `% 8 == 0`。
2. 其余位置**没有 padding**，因此**没有"padding 字节填什么"这个问题**。
   也不引入"必须校验 padding 为零"这条规则——不存在的东西不需要校验。
3. 刻意**不用**对齐指令去做无意义的对齐：本格式的内容布局本身紧凑且自描述，
   额外对齐只会让同一语义产生多种字节编码，从而破坏 §8 的规范形式。

> **保留 8 对齐的理由不是今天需要**：加载器今天是老实拷贝进 `Vec<Insn>`。
> 它保的是**未来 mmap 零拷贝**这条路——页对齐基址 + 段偏移 8 对齐即可直接重解释，
> 不需要改动格式。为一个几 KB 的文件省一次 memcpy，不值得让格式带上 unaligned 的原罪。

## 5. 代码段

- `8 × code_len` 字节，逐条小端 `u64`，编码见 `isa.md` §1.1。
- **不压缩、不 varint、不变长。** 任何 varint 编码都会把指令字撑到 9~10 字节
  （opcode 占 bit 63..56，使绝大多数指令字 ≥ 2^56），即 **+12.5% ~ +25%**，
  这是本格式绝不能接受的。
- 代码段的字节偏移 ↔ 指令下标关系恒为 `off = 96 + 8 × pc`。
- 最后一条必须是 `HALT`（§9.3 I8）；binder 负责补齐。

## 6. 元数据表

五张表，**顺序固定、零间隙**、元素数与固定头里的 count 一致。
表内**没有长度前缀**，长度由逐元素解析得出。

### 6.1 名字编码

```
名字 := 一个或多个字节的 UTF-8，后跟一个 0x00 终止字节
```

- 空名字（首字节即 `0x00`）**非法**。
- 名字必须匹配 `[A-Za-z_][A-Za-z0-9_]*`，即 ASCII 标识符。
  这是 **v1 的收紧决定**（不是从 `isa.md` 推导出来的）：名字会出现在绑定、错误消息与调试信息里，
  而绑定的正确性依赖**逐字节相等**；允许任意 UTF-8 只会给"看起来一样实则不同"的冒名者留门。
  若将来确实需要非 ASCII 名字，放宽为"合法 UTF-8 且不含 NUL"，但必须同时接受放弃同形异义防护。
- 名字**在同一张表内必须唯一**（§9.2 M2）。

### 6.2 `muscles` — `muscle_count` 项

```
muscle := 名字
```

**下标即 muscle id**，也即 `Task.values` / `set_mask` 的下标。表内顺序是**程序语义的一部分**。

> **读回不变量（硬性）**：对每个 `m < muscle_count`，`sensors_f[m]` 必须是 `muscles[m]` 的读回通道，
> 即 `name` **逐字节相同**且 `src == MUSCLE`。
> 于是 `FSENSE rd, mouth_open` 与 `FEXCITE mouth_open, ra` 的 `imm` 是**同一个整数**，
> bind 时不需要"肌肉 ↔ 读回 sensor"的映射表，运行期也不需要一层间接。

### 6.3 `sensors_f` / `sensors_i` — `sensor_f_count` / `sensor_i_count` 项

```
sensor := 名字  源类型(u8)
```

| `src` | 名称 | 合法位置 | 含义 |
|---|---|---|---|
| 0 | `MUSCLE` | 仅 `sensors_f`，且仅 `index < muscle_count` | 该肌肉当前值的读回（后端推进后的值） |
| 1 | `BACKEND` | 两者皆可 | 后端可观测量，按名字绑定 |
| 2 | `BUILTIN_DT` | 仅 `sensors_f`，至多一个 | 内置 `dt`（§4.7） |
| 3 | `BUILTIN_TICK` | 仅 `sensors_i`，至多一个 | 内置 `tick`（§4.7） |

`MUSCLE` 项的出现位置与名字由读回不变量强制，加载期逐项比对。
`dt` / `tick` **不占魔法下标**：它们就是普通表项，所以代码里没有"内置 sensor 排第几"这种隐含约定。

### 6.4 `vars_f` / `vars_i` — `var_f_count` / `var_i_count` 项

```
var_f := 名字  初值(u32 = f32 位模式)
var_i := 名字  初值(i32)
```

- 浮点与整数是**两个独立 id 空间**，各自 0 基址（§2.4）。
- 初值按**位模式**存储，因此可以嵌入任意 f32（含 NaN / ±Inf / 非规格化数），与 `FMOVI` 同理。
- 变量随任务结束消亡；跨动作存活的状态用永不 `HALT` 的任务表达（§2.4），不要引入全局变量。

### 6.5 索引语义

| 表 | `imm` 的含义 | 相关指令 |
|---|---|---|
| `muscles` | muscle id | `FEXCITE` |
| `sensors_f` | 浮点 sensor id | `FSENSE` |
| `sensors_i` | 整数 sensor id | `ISENSE` |
| `vars_f` | 浮点变量 id | `FVGET` / `FVSET` |
| `vars_i` | 整数变量 id | `IVGET` / `IVSET` |

这五张表就是 `isa.md` §13.2 里「逻辑 id」的全部来源。

## 7. 内容哈希

```
content_hash = blake3(file[0 .. file_len - 32])
```

- 存于文件**最后 32 字节**。覆盖范围因此是一句话：**除最后 32 字节的全部**。
  不需要"把哈希字段视为 0"这类自指规则，头里也不留空洞。
- 用途：缓存键、版本比对、损坏检测——§10 #6 的「唯一规范形式」服务的正是这件事。
- **不覆盖**调试信息（在 `.cspd` 里），因此补调试信息不会改变程序哈希。
- 绑定期缓存键：`hash(program_hash, rig_binding_hash)`（见 `isa.md` §9.4.2）。

## 8. 规范形式（canonical form）

> 语义相同的两个动作，其 `.csp` 字节**逐位相同**。

这是**构造性**保证，不靠额外的"规范化"步骤：

1. 布局全推导（P3）：没有偏移字段、没有长度字段、没有对齐间隙可供写作者自由发挥。
2. 五张表的顺序与元素顺序都被程序语义固定。
3. 名字唯一（§9.2 M2），因此不存在"同一张表两种排列"。
4. 未使用字段必须为 0（§9.3 I2）。

于是哈希可以直接当**内容标识**用——这正是 §10 #6 想要的东西。

## 9. 加载期校验清单

`isa.md` §10 的第 1~10 条继续有效（其中第 4 条现在才第一次**可实现**：单元边界就是 `[0, code_len)`）。
本节新增容器级与元数据级条款；**全部为 O(n) 一次扫描，运行期零成本**。

校验顺序：**C（容器）→ M（元数据）→ I（指令）**。全部通过后产出的镜像视为可信，
运行期不再有任何边界检查（`isa.md` §0.4 第 5 条）。

### 9.1 容器级

| # | 规则 |
|---|---|
| C1 | `file_len ≥ 136`；`magic` 匹配；`file_len` 精确等于实际字节数 |
| C2 | `format_version` major 相等且 minor ≤ 本加载器；`isa_version`、`cycle_table_version` 在支持集内 |
| C3 | `flags`、`reserved0`、`reserved1`、`reserved2` 全为 0 |
| C4 | `hz > 0`；`max_wait_bits` 是非负有限 f32；`cycles_per_tick ≥` 计费表最贵指令的周期数 |
| C5 | **计数 sanity**：由各 count 与 `code_len` 导出的**最小总长下界**（每条指令 8 字节，每个表项至少 2 字节）必须 ≤ `file_len`。**必须在分配任何 `Vec` 之前执行** |
| C6 | `content_hash` 与 `blake3(file[..file_len-32])` 相等 |
| C7 | 解析后游标**精确**停在 `file_len`（哈希之前不允许尾随字节） |
| C8 | `code_len ≥ 1` 且 `code[code_len-1]` 是 `HALT` |

> **C5 是防分配炸弹的那一条**，也是"两步加载"的理由：必须先读固定头 → 校验计数 → 再整体解析。
> 若一步到位地按 `count` 预分配向量，一个 `count = 4×10⁹` 的坏文件就能把加载器打死。
> C6 放在 C5 之前更好：哈希一票否决绝大多数的坏文件，且不需要任何解析。

### 9.2 元数据级

| # | 规则 |
|---|---|
| M1 | 每个名字非空、合法 UTF-8、匹配 `[A-Za-z_][A-Za-z0-9_]*` |
| M2 | 每张表内名字**唯一**（否则绑定有二义） |
| M3 | `sensor_f_count ≥ muscle_count` |
| M4 | 读回不变量：对全部 `m < muscle_count`，`sensors_f[m].name == muscles[m]`（逐字节）且 `src == MUSCLE` |
| M5 | `src` 取值合法且位置合法；`BUILTIN_DT` / `BUILTIN_TICK` 各至多一个 |
| M6 | `MUSCLE` 只出现在 `sensors_f`，且只出现在 `index < muscle_count` |

### 9.3 指令级（`isa.md` §10 的 1~10 条，落到可执行的判据）

| # | 规则 | 判据 |
|---|---|---|
| I1 | opcode 属于已定义指令，保留 opcode 一律拒绝 | 解码失败即拒绝 |
| I2 | **未使用字段必须为 0** | **`decode(insn)` 后重新 `encode` 必须逐位等于原字**。这一个等式同时覆盖「无 `imm` 语义指令的 `imm`」与「该指令不使用的 `rd`/`ra`/`rb`/`rc`」两类 |
| I3 | `FSENSE` / `ISENSE` 的 index < 对应 sensor count | |
| I4 | `FVGET`/`FVSET` 的 index < `var_f_count`；`IVGET`/`IVSET` 的 index < `var_i_count` | |
| I5 | `FEXCITE` 的 index < `muscle_count` | |
| I6 | 跳转目标 `pc + 1 + off ∈ [0, code_len)` | 必须调用 `isa.md` §1.3 要求的**唯一**偏移计算函数 |
| I7 | `WAIT` 的 `imm` 是非负有限 f32，且 ≤ 头段 `max_wait` | |
| I8 | 最后一条指令是 `HALT` | |

> **I2 值得展开**：它把"唯一规范形式"这条要求交给一个**可往返测试的等式**，
> 而不是交给一份"哪些字段该为 0"的手工清单。手工清单会随指令增加而腐烂，等式不会。
> 代价是编码器必须**只写该指令真正使用的字段**，其余一律置 0——这条对汇编器同样有约束力。

> **I6 的边界**：`isa.md` §5.3 写作「目标必须在 `[0, code_len]` 内」，其中 `code_len` 指隐式 `HALT`
> 的下标。本文件把 `code_len` 定义为**指令条数**，于是判据就是 `target < code_len`，
> 「跳到末尾」= 跳到下标 `code_len-1` 的那条 `HALT`。两种写法等价，但实现只允许有一种。

## 10. 版本与演进

| 变更类型 | 处理 |
|---|---|
| 新增指令 | `isa_version` +1；旧加载器必须拒绝（不认识的 opcode 会在 I1 挂掉） |
| 改周期计费表 | **新增** `cycle_table_version`，不得重定义已发布的表（§6.3） |
| 追加元数据表（旧程序语义不变） | 只加 `format_version` minor。新表只能**追加在最后一张表之后**；旧程序的对应 count 为 0，因此仍可解析 |
| 改变已有字段含义 / 移动固定头字段 | `format_version` major +1，加载器按 major 分派不同固定头布局 |
| 扩固定头字段 | 只能用 `reserved` 区；固定头长度**必须保持 8 的倍数** |

## 11. 本文件对 `isa.md` 的修订建议

写这份格式规范时发现下面几处需要回改 `isa.md`（都属于**文档一致性**，不改变已冻结的语义）：

1. **`fuel` 缺省值缺失**。§7.1 只说头段声明 `fuel_default`，没给值。v1 暂定 **4096**。
2. **术语不统一**：G3「单元入口」、§5.3「当前单元」、§13.2「程序镜像」指的是同一个东西。
   既然 1 文件 = 1 动作，建议统一为「单元」，并在 §0 明确「单元 ≡ 一个动作 ≡ 一个 `.csp` 文件」。
3. **§7.1「可选的单元级覆盖」应删除**：没有多单元，就没有覆盖层级。
4. **§4.12 汇总与 §4.5 助记符不一致**：§4.5 是 `ITOF`/`FTOI`，§4.12/§6.2/§11 是 `I2F`/`F2I`。
   需要二选一（现有 `src/vm/op.rs` 用的是 `Itof`/`Ftoi`，建议以 §4.5 为准）。
5. **§6.2 周期表漏了 `IMOVI`**：§4.1 有 4 条传送指令，表里只列了 3 条再加 `NOP`，
   按行统计只有 47 条。补 `IMOVI = 1` 后恰好 48 条。
6. **§6.3 的计费表版本没有落在头段声明里**。§13.1 必须补上 `cycle_table_version`，
   否则 `cycles_per_tick` 与 §10 #10 的校验都没有指称对象。
7. **§10 缺少容器级与元数据级条目**：见本文件 §9.1 / §9.2。
   特别是 §10 第 4 条「跳转目标在当前单元内」在没有单元边界定义时无法实现。

## 附录 A：实现备忘（binrw 0.15 映射）

将来实现时用 `binrw` 的声明式布局表达本文件。要点（**不是代码，只是映射表**）：

| 本文件的要素 | `binrw` 表达 |
|---|---|
| 固定头整体 | 一个 `#[binrw] #[brw(little, magic = b"CSPX")]` 的结构体，字段顺序**严格**按 §4 的表 |
| 五张表 | 同一结构体内依次排列的 `Vec<T>` 字段，`#[br(count = <固定头字段>)]`，写侧不输出长度 |
| 名字（§6.1） | `binrw::NullString`（NUL 结尾，内建，读写对称，无需自写编解码） |
| 哈希（§7） | 尾部 `#[br(count = 32)] Vec<u8>`；校验在结构体之外对原始字节做 blake3 |
| 对齐（§4.1） | **不用**任何对齐指令。固定头 96 字节这一事实本身就是全部对齐保证 |
| C3/C4/C5 等跨字段校验 | 结构体级的 `assert` / `pre_assert` 指令，或（推荐）解析后独立的一次遍历，以便给出精确错误 |

三点实现注意：

1. **必须两步加载**：先单独解析固定头（96 字节，无 `Vec`）→ 执行 C1~C6 → 再整体解析。
   否则 C5 形同虚设（`binrw` 会按 `count` 预分配）。
2. `binrw` 的 `align_before` / `pad_size_to` / `seek_before` **在 v1 里一个都不使用**。
   它们是为将来出现真正的定长/对齐数据结构准备的；现在用上只会制造非规范的第二编码。
3. `cycle_table_version` 的周期表本身不属于本文件——它属于 `isa.md` §6.2，
   但**必须带版本**并随加载器一起提供，供 C4 与 §9.3 使用。
